How to count the lines in your text files

Short answer

A folder of exported notes gives no hint of its size until you open every file. This lesson builds a small read-only Python tool that counts the lines in each text file of a folder and shows a small table: Windows, Mac and Linux endings all count, a last line without an ending still counts, and blank lines are listed in their own column. The tool has no code that changes, moves or deletes anything.

Follow along and build it step by step. You add each file yourself, run each command, and see the real recorded result.

Common mistakes

  1. Counting newline characters instead of lines. A file whose last line has no ending is undercounted, and old Mac endings are missed entirely.
  2. Treating a line count as a quality measure. A long file is not a good file and an empty one is not useless. The count is only a size hint.
  3. Expecting subfolders to be included. The tool stays at the top level of the folder you name. Files inside subfolders are not counted.

Frequently asked questions

Why does a line of spaces not count as blank?

Blank here means no characters at all. A line holding only spaces looks empty in an editor but is not, so the tool counts it as a normal line.

Does it handle Windows line endings?

Yes. It splits lines with Python's splitlines, which treats Windows CRLF, Mac/Linux LF and old Mac CR all as line endings.

Will it change my files?

No. It only reads. One test checks that the source has no code that writes, and another checks that a folder, including its files' sizes and changed times, is exactly the same after a run.

What about Word documents or PDFs?

No. Only plain text saved as UTF-8 is counted. Anything else is skipped, with a note at the end of the report.

Where do the recorded results come from?

From running the exact commands shown, on the machine and date named in the About box. Your numbers will differ on your own files.
